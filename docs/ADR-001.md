# ADR 001 — Prototype architecture and corrections to draft v0.1

Status: provisional, pending device measurements. Date: 2026-09-26.

## Implementation choices

TypeScript modules express the protocol and simulation; React renders the shell and schema-driven phone UI; Canvas 2D renders a canonical 16:9 game surface. Vite/Vinext supplies the local frontend and build validation; hosting is deferred. A small Node `ws` process supplies ephemeral room identity, SDP/ICE signaling, and fallback forwarding. WebRTC carries the primary two-tier data path. Room identity allocation is delegated to signaling; scoring and game lifecycle remain in the host browser.

The host owns one inter-venue connection per remote venue plus its venue's phone connections. A single venue has no inter-venue connection. A remote phone only opens a direct host connection when its primary venue data channel is unavailable after eight seconds. WebSocket relay is a degraded path, not a LAN guarantee. Unreliable channels use `ordered:false,maxRetransmits:0` and drop frames under backpressure. Reliable controls and game events use separate ordered channels.

Minigames currently run as bundled modules. Configure, frame, snapshot and results data are cloned; remote rendering never calls the simulation. The Node clone benchmark is included, but selecting iframe isolation requires a real browser MessageChannel/iframe test. No benchmark number proves physical latency.

## Necessary specification corrections

1. **Geography does not imply a LAN route.** Client isolation, mobile data, ICE candidate selection and TURN may route even co-located devices through the internet. Inspect the selected candidates. Path A is a measurable goal conditional on reachability.
2. **Equal delay added on arrival does not equalize presentation.** A Display samples the common authority timeline at `syncedNow - D`. D includes the worst measured downstream p95 plus two snapshot intervals (80 ms at a 25 Hz target) and a 10 ms safety margin, once. It ramps at 50 ms per second. Single-venue target D is zero. Snapshot starvation is counted when that margin is insufficient.
3. **Interpolation and zero delay cannot both have future samples.** Single-venue D=0 deliberately holds the latest authoritative snapshot; own cursors still update immediately. Remote smoothness is bought with a shared interpolation horizon.
4. **Counters alone cannot recover an action's original timestamp or aim.** The 47-byte continuous frame repeats the last timestamp for each of four semantic button slots. A separate reliable journal message captures each press's exact time and aim. Both paths deduplicate by player, configuration generation, slot, counter and timestamp. The frame path can recover an edge promptly; the journal preserves multiple intervening presses. The first recovered representation wins, so if the frame arrives before the journal, aim can reflect the recovery frame. Exact historical aim after packet loss remains a limitation for a future precision-shooter game.
5. **Timestamp arbitration requires an acceptance window.** Presses mature 200 ms after their action timestamp, then are processed in timestamp order. Late presses are processed immediately without rollback if their current game's judgment window is still open. This is a visible resolution-latency cost; timestamps do not erase causal delay. Reaction targets are scheduled ahead of their presentation time. Their scores use action time minus scheduled appearance, not arrival time.
6. **A hand-fitted H need not map the tangent origin to exactly (0.5, 0.5).** Recenter first inverts H at the screen center, then adjusts only the quaternion reference to map the current pose there. H is untouched. Arbitrary seat/roll changes can still require recalibration; moving the physical screen does not magically preserve angular geometry.
7. **A u32 microsecond timestamp wraps every ~71.6 minutes.** Decode to the epoch nearest the Session clock. Configuration generations reject frames from old rounds/layouts. Every new controller process announces a boot identity and receives a fresh configuration epoch, so a reloaded phone’s reset sequence is accepted while old in-flight frames are rejected.
8. **There is networking in the first spike.** A phone-to-screen cursor needs a transport, even without a Session. The implementation provides the full graph; a same-room two-phone round isolates the local path.
9. **TV panel latency and Game Mode cannot be measured from ordinary browser timers.** The HUD says unmeasured and accepts a camera result. It does not infer an unsupported hardware claim.

## Boundaries and upgrade path

No deterministic lockstep, media streaming, accounts, matchmaking, authority migration, or cloud-authoritative game simulation. The server can later host the same cloneable game contract, replacing host-loss and host-bandwidth limitations. It would also need a trusted clock and appropriate action/history policy.

The provided games select `freeze` on disconnect. The lifecycle contract raises dropped/returned hooks; pause extends the timeline and ends cleanly on grace expiry, while substitute supplies a basic steering/tracking bot. More sophisticated game-specific AI remains the game author’s responsibility. Generic widgets are fixed client primitives. New games may consume their semantic values without shipping controller-specific code.
